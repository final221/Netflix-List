## R01 — remove unused handlers and unnecessary interface entries

**Ready; small, low-risk reduction.**

- `src/app/responsive.js:476`: `handleTargetWindowResize` and `handleTargetVisualViewportResize` have no references. The actual start method installs revision-guarded closures calling `handleTargetResize` directly. Remove the two obsolete functions, retain the active listener/retirement path.
- `src/grid/grid.js:122–125`: public `clearRetained` and `orderChildren` have no callers in source or tests. Remove the exported operations, with the now-unused `clearRetained` alias from private cards. Keep exact `releaseRetained`, disposal clearing and the private guarded ordering operation used by groups.
- `src/list/list.js:22`: public `buildItems` has no consumers. Keep the internal builder used by collection strategy, remove the unnecessary public entry.
- `src/viewing/viewing.js:69`: private-policy `readCache` alias has no consumers; initialization directly uses the cache owner. Keep cache validation/read/write/profile semantics.

This is removal of obsolete handlers and unnecessary access paths, not relocation of code. A temporary prototype measured **16,457 lines / 938,715 authored bytes** and **888,613 generated bytes**: **11 fewer lines, 454 fewer authored bytes, 490 fewer generated bytes**. Build, output/dependency checks and all **531 unmodified tests** passed. Every modified file/artifact was restored byte-for-byte afterward. This proves a modest concrete opportunity, not a large saving.

Acceptance for implementation: reference review; unchanged active resize callbacks and exact resource retirement; preserved private group ordering/cache/Undo ownership; full check/test/build gates; patch release and generated-output review. Do not remove `moveCard`, `toRecord`, `collectLogical` or card-control APIs simply because application composition does not call them: existing public-contract tests use them and their owner behavior remains meaningful.

## R02 — consolidate initialization failure reporting

**Next bounded candidate; implementation/prototype not yet performed.**

`src/app/my-list-session.js` constructs `initializationFailed` diagnostics **seven times**: mismatch reinitialization, initial count, missing native source, readiness, indicator normalization, mounted count confirmation and final collection/publication. The blocks contain about 54 lines of repeated diagnostic object construction, plus nearby repeated status formatting.

Put the common report construction in one session-local operation. Callers retain their phase-specific stage/timeout/count defaults, blocked-source eligibility, original source identity, cancellation treatment, rescheduling and exact deferral release. Avoid turning distinct outcomes into a generic retry. The readiness and mismatch reports intentionally differ in exported fields; decide and test the diagnostic contract rather than silently standardizing it.

This can reduce repeated representation and make changes to diagnostic fields local. It does **not** justify deleting the stage-specific catch/cleanup branches or collapsing the whole initialization state machine. Net savings must be measured after implementation; 54 repeated lines are not a promised 54-line reduction because the shared operation and arguments still need code.

Evidence to retain: blocked initialization/recovery/exhaustion, preferred/native failure, route retirement, construction cancellation, mismatch acceptance/cancellation and busy-action release. Add or strengthen a focused diagnostic assertion only where moving reporting would otherwise lose a distinct stage/default; existing end-to-end cases should remain. Sensitivity should expose an incorrect stage/default or old-session report, not merely a call to a new helper.

## R03 — converge on one record/material transfer path

**Largest conceptual opportunity found; conditional and more involved.**

Relevant code: `src/grid/cards.js:35–65`, `src/grid/grid.js:32–58`, `src/list/collection.js:165–196`, plus native mutation admission in `src/list/mutations.js`. Startup already supplies frozen scalar records plus separately staged material/page readers and an explicit release callback. Grid also accepts older mutable inputs containing snapshot/cardTemplate and has its own fallback startup-release logic. List's transfer independently resolves those fields and releases captured input material.

A useful destination is one capture-to-record/material transfer contract, with list owning conversion/admission and grid owning current/retained rendered material. It could remove duplicate material interpretation/release branches and reduce the supported forms of grid input. Keep initial/native GraphQL capture separate from lasting membership and keep exact retained Undo correlations.

**This is not currently dead code.** A disposable probe made embedded snapshot/template reads and legacy startup release fail if reached, rebuilt the actual artifact, then ran app, bundle and session workflow tests. Native Undo and pending addition failed at `hasMaterial` before conversion, with asynchronous failure evidence too. This proves native mutation admission still depends on the snapshot path. All probe changes were restored, and the original artifact passed check afterward.

Implementation therefore requires changing admission/transfer coherently, not deleting the fields or weakening tests. Do not consume captured markup before accepted insertion; rejection, stale ownership or a replaced source must leave it available to the correct owner. Do not change retained Undo order or expire/release a newer capture. Existing focused grid tests using mutable fixture input must be adapted to the canonical public transfer while preserving their card replacement, reentrant failure, material cleanup and Undo assertions; deleting those tests would be loss of protection.

Acceptance: startup in both collection modes, mounted/fresh/native fallback, add before/after native convergence, retained/native Undo, missing material, correlated expiry, reentrant replacement, cancellation and chunked publication. Repeat targeted sensitivity and all gates. Measure net authored/generated size only after replacing both paths; no reliable saving is claimed yet.

## What should stay

- Logical and indicator carousel modes, wrapped-tail repair, source/count proof and bootstrap/native fallbacks have separate native input contracts.
- Generation/token/handle checks protect different route, source, request, mapping and card lifetimes. Similar-looking checks do not prove redundant ownership.
- The read-only responsive view preserves session ownership and rejects obsolete acceptances; replacing it with a shared writable parent would undo the implemented boundary.
- Diagnostics, localization, native React replay and physical pointer/departure behavior are capabilities. Removing them would change the product goal.
- Small list/grid/viewing facade files enforce useful dependency boundaries. Their file count is not a reason to inline private owners into the page coordinator.
- The 531 tests should be retained for this work. No pair has been proven equivalent in contract, input class and failure mode, so test-count reduction is not proposed.

## Recommended execution order

R01 first as a measurable baseline. R02 next while preserving phase-specific outcomes. R03 only as a coherent transfer-boundary change with the existing mutation/material guards proven. Each remains a separate bounded change, with a patch version/build if the distributable is published. A candidate is successful only if it removes a representation, branch or access path while preserving its guards and outputs; a smaller line count alone is insufficient.

This assessment changes documentation only. Main and the shipped userscript remain 1.4.59; no temporary runtime prototype survives.


## R01–R03 implementation completed — 2026-10-08

The user subsequently authorized all three in one run. Version **1.4.60** implements them on `codex/essential-code`; main remains 1.4.59 until separately merged.
